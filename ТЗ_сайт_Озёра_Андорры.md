# Техническое задание: веб-сайт «Озёра Андорры»

**Версия:** 1.0 · **Дата:** 28.09.2026

---

## 1. Назначение и общее описание

Сайт о пеших маршрутах (хайкинге) к горным озёрам Андорры и приграничных районов Франции и Испании, куда маршруты начинаются из Андорры.

Главная страница — схематичная карта Андорры и прилегающих участков Франции и Испании в стиле старой туристической карты, с точками-озёрами и их названиями. Клик по точке (или по названию) открывает поверх карты окно озера: фотографии, ссылки на начало маршрута и на само озеро в Google Maps, ссылка на маршрут в Komoot и встроенная карта маршрута Komoot. Окно закрывается — снова видна карта со всеми точками.

**Ключевое требование:** сайт наполняется без программирования. Заказчик добавляет подпапку с новым озером (фото + текстовый файл со ссылками), публикует изменения — и на карте автоматически появляется новая точка.

## 2. Принятые решения (по итогам опроса заказчика)

| Вопрос | Решение |
|---|---|
| Хостинг | Бесплатный статический хостинг — **GitHub Pages** |
| Обновление сайта | Папка проекта — git-репозиторий; добавление подпапки → `commit`/`push` (или запуск скрипта `publish.bat`) → **GitHub Actions** пересобирает и публикует сайт |
| Координаты озёр | **Автоматически** из ссылки `end point` (раскрытие короткой ссылки Google Maps) + возможность **ручного указания** в txt (имеет приоритет) |

| Карта | **Рисованная SVG-схема + стилизованный рельеф** |
| Визуальный стиль | **Старая туристическая карта** |
| Страница озера | Фото, 3 ссылки, **встроенная карта маршрута Komoot** |
| Фотографии | **Галерея миниатюр + лайтбокс** (полноэкранный просмотр), автоматическое сжатие при сборке |
| Главная, кроме карты | **Список озёр** |
| Название сайта | **«Озёра Андорры»** |
| Структура папок | Подпапки озёр переносятся в папку **`lakes/`** |

## 4. Формат данных озера

### 4.1. Подпапка озера

- **Имя подпапки = отображаемое название озера** (например, `Etang Fourcat`). Допускаются пробелы, апострофы, диакритика.
- Из имени автоматически формируется URL-идентификатор (slug): латиница в нижнем регистре, пробелы → дефисы, диакритика и апострофы удаляются. Пример: `Estany de l'Isla` → `estany-de-lisla`.
- Подпапки, имя которых начинается с `_` или `.`, игнорируются (черновики).

### 4.2. Файл `points on the map.txt`

Текущий формат сохраняется без изменений:

```
start point: https://maps.app.goo.gl/Nnm3sFPtaGAU1CJn6
end point: https://maps.app.goo.gl/e2VKY4sndWh27TLV8
route: https://www.komoot.com/tour/3315307999/zoom
```

Необязательные дополнительные строки:

```
coords: 42.6034, 1.5712        ← координаты озера вручную (приоритетнее автоматических)
label: left                    ← сторона подписи на карте: left / right / top / bottom (если автоматическая раскладка неудачна)
cover: IMG_7295.JPEG           ← фото-обложка (по умолчанию — первое фото)
```

Требования к разбору файла:
- имя файла ищется без учёта регистра;
- ключи — без учёта регистра и лишних пробелов, разделитель `:`;
- допускаются кодировки UTF-8 (с BOM и без) и Windows-1251, переводы строк CRLF/LF;
- неизвестные строки игнорируются с предупреждением в логе сборки.

### 4.3. Фотографии

- Поддерживаемые форматы: `.jpg`, `.jpeg`, `.png`, `.webp` (без учёта регистра, т.е. `.JPEG` тоже). `.heic` — конвертируется, если это поддерживает библиотека обработки; иначе файл пропускается с предупреждением.
- Порядок: по дате съёмки из EXIF, при её отсутствии — по имени файла.
- Оригиналы не изменяются.

## 5. Сборка сайта (скрипт `scripts/build`)

Технологии: **Node.js** (LTS), библиотека **sharp** для изображений, **exifr** для EXIF. Фронтенд — чистые HTML/CSS/JavaScript без фреймворков.

Шаги сборки:

1. **Сканирование** `lakes/`: каждая подпапка = одно озеро.
2. **Разбор** `points on the map.txt` (п. 4.2).
3. **Координаты озера** — в порядке приоритета:
   1. строка `coords:` в txt;
   2. запись в `data/geocache.json` (ключ — URL ссылки);
   3. раскрытие короткой ссылки `end point`: HTTP-запрос с отслеживанием редиректов, извлечение координат из итогового URL (шаблоны `@lat,lon`, `!3dLAT!4dLON`, `?q=lat,lon`, `ll=`). Результат записывается в кэш.
   
   Аналогично раскрываются координаты `start point` (сохраняются в данные на будущее, на карте пока не используются).
4. **Страна** озера (Андорра / Франция / Испания) определяется автоматически по координатам (попадание точки в полигон границы). Используется в списке озёр и в окне озера.
5. **ID маршрута Komoot** извлекается из ссылки `route` (`/tour/<число>`), формируется адрес встраивания `https://www.komoot.com/tour/<ID>/embed?profile=1`.
6. **Обработка фото:**
   - автоповорот по EXIF;
   - миниатюры ~480 px по длинной стороне, WebP;
   - полноразмерные ~2000 px по длинной стороне, WebP + JPEG-запасной вариант;
   - **удаление EXIF (включая GPS)** из опубликованных копий;
   - уже обработанные фото не пересчитываются (кэш по имени, размеру, дате изменения файла).
7. **Генерация** `lakes.json` с данными всех озёр и сборка страницы в `dist/`.
8. **Отчёт в консоли**: сколько озёр найдено, предупреждения по каждому проблемному озеру.

### 5.1. Обработка ошибок (сборка не должна падать из-за одного озера)

| Ситуация | Поведение |
|---|---|
| Нет txt-файла | Озеро пропускается, предупреждение |
| Не удалось получить координаты | Озеро есть в списке с пометкой «нет на карте», предупреждение с подсказкой добавить `coords:` |
| Координаты вне области карты | Точка не рисуется, предупреждение (значит, нужно расширить подложку, см. п. 6.3) |
| Нет фото | Окно озера показывается с заглушкой вместо галереи |
| Нет/некорректная ссылка Komoot | Блок Komoot не показывается |
| Битый файл фото | Файл пропускается, предупреждение |

Сборка завершается с ошибкой, только если в `lakes/` не найдено ни одного валидного озера.

### 5.2. Команды

- `npm run build` — сборка в `dist/`;
- `npm run dev` — локальный просмотр с автопересборкой при изменении `lakes/`.

## 6. Главная страница

### 6.1. Композиция

- **Десктоп (≥ 1024 px):** карта занимает основную часть экрана, справа — узкая панель «Список озёр».
- **Планшет/телефон:** карта на всю ширину; список озёр — под картой (или выдвижная панель по кнопке «Список озёр»).
- Заголовок-картуш на карте: **«Озёра Андорры»** и подзаголовок (например, «Пешие маршруты к горным озёрам»).

### 6.2. Карта: содержание

- Границы Андорры, Франции, Испании; подписи стран (ANDORRA / FRANCE / ESPAÑA или по-русски — АНДОРРА / ФРАНЦИЯ / ИСПАНИЯ).
- Основные населённые пункты: Андорра-ла-Велья, Эскальдес-Энгордань, Энкамп, Канильо, Ордино, Ла-Массана, Сант-Жулия-де-Лория, Пас-де-ла-Каза, Сольдеу; во Франции и Испании — ближайшие к границе (например, Л'Оспиталет, Ла-Сеу-д'Уржель).
- Основные дороги между основными населёнными пунктами.
- Основные реки (Валира и её притоки).
- Несколько главных вершин с отметками высот (например, Кома-Педроза, 2942 м).
- **Стилизованный рельеф**: отмывка и/или штриховка (хашюры).
- Элементы оформления: роза ветров, масштабная линейка, легенда.
- **Точки-озёра**: значок в виде маленького озера или капли + подпись названием подпапки.

### 6.3. Карта: техника

- Карта строится как **SVG**. Контуры границ, реки, дороги, населённые пункты берутся из открытых данных (OpenStreetMap / Natural Earth), упрощаются и хранятся в `map/`.
- Рельеф — заранее подготовленная растровая подложка (из открытой ЦМР, например Copernicus DEM или SRTM), стилизованная под старую карту. Готовится **один раз** и лежит в репозитории.
- **Область подложки** с запасом: примерно 42.30–42.85° с. ш., 1.20–2.00° в. д. (Андорра + ~20–25 км во Францию и Испанию). Видимая область карты по умолчанию — вся Андорра с приграничьем; при необходимости автоматически расширяется, чтобы вместить все озёра.
- Проекция — Web Mercator (или равнопромежуточная, для такой малой территории разница несущественна); координаты озёр пересчитываются в координаты SVG автоматически.
- **Масштабирование и панорамирование**: кнопки «+ / −», колесо мыши, pinch-жест на телефоне. Нужно, потому что озёра могут располагаться близко друг к другу.
- **Подписи не должны перекрываться**: автоматическая раскладка подписей (сдвиг влево/вправо/вверх/вниз, при нехватке места — выноска-линия). Ручная подсказка — строка `label:` в txt.
- При наведении на точку/подпись — подсветка точки и соответствующей строки в списке, всплывающая подсказка с миниатюрой обложки.

### 6.4. Список озёр

- Все озёра в алфавитном порядке; у каждого — название, страна (флажок или метка), миниатюра обложки.
- Клик по строке открывает окно озера (как клик по точке).
- Наведение на строку подсвечивает точку на карте.
- Озёра без координат показываются в списке с пометкой «нет на карте».

## 7. Окно озера (модальное окно)

### 7.1. Поведение

- Открывается **поверх главной страницы** (полупрозрачное затемнение под окном, карта видна по краям).
- Размер: на десктопе ~80% ширины экрана (не более ~1100 px), на телефоне — на весь экран.
- Закрытие: кнопка «×», клавиша `Esc`, клик по затемнённой области, кнопка/жест «Назад» в браузере.
- **Адрес страницы меняется** на `#/lake/<slug>`: окно конкретного озера можно открыть по прямой ссылке и отправить ссылку другу. При закрытии адрес возвращается к главной.
- Прокрутка страницы под окном блокируется, пока окно открыто.
- При закрытии фокус возвращается на точку/строку, с которой окно открыли.

### 7.2. Содержимое (сверху вниз)

1. **Заголовок** — название озера, под ним страна.
2. **Кнопки-ссылки** (открываются в новой вкладке):
   - «📍 Начало маршрута» → `start point` (Google Maps);
   - «🏞 Озеро на карте» → `end point` (Google Maps);
   - «🥾 Маршрут в Komoot» → `route`.
3. **Галерея**: сетка миниатюр; клик открывает лайтбокс.
4. **Встроенная карта Komoot** (iframe): загружается только при открытии окна (не при загрузке главной). Если маршрут не публичный или встраивание не загрузилось — показывается только ссылка.

### 7.3. Лайтбокс

- Фото на весь экран на тёмном фоне, счётчик «3 / 4».
- Навигация: стрелки на экране, клавиши ← →, свайп на телефоне; закрытие — «×», `Esc`, клик по фону.
- Закрытие лайтбокса возвращает в окно озера (а не на главную).
- Предзагрузка соседнего фото.

## 8. Визуальный стиль «Старая туристическая карта»

- **Палитра:** тёплый бумажный фон (кремовый/беж, лёгкая текстура бумаги), сепия и коричневые тона рельефа, приглушённый зелёный для лесов/долин, голубовато-бирюзовые озёра, тёмно-коричневые контуры и шрифт, приглушённый красный для акцентов (точки, выделение).
- **Шрифты** (обязательно с поддержкой кириллицы): антиква с «старинным» характером для заголовков и подписей (например, Old Standard TT, Cormorant, Playfair Display) и хорошо читаемая антиква для текста (например, PT Serif). Подключение через Google Fonts.
- **Детали:** картуш с названием, двойная рамка вокруг карты, роза ветров, масштабная линейка «в старинном стиле».
- Окно озера — в той же стилистике (бумажный фон, рамка), но фото показываются без стилизации, в натуральных цветах.
- Светлая тема обязательна; тёмная тема — не требуется.

## 9. Публикация и обновление

### 9.1. Первичная настройка (выполняет исполнитель)

1. Инициализировать git-репозиторий в папке проекта, перенести подпапки озёр в `lakes/`.
2. Создать репозиторий на GitHub (аккаунт заказчика), настроить GitHub Pages (источник — GitHub Actions).
3. Workflow `.github/workflows/deploy.yml`: при push в ветку `main` — установка Node.js → `npm ci` → `npm run build` → публикация `dist/` на GitHub Pages. Кэшировать обработанные фото между запусками (actions/cache), чтобы сборка не пересчитывала все фото каждый раз.
4. Скрипт `publish.bat`: `git add lakes` → `git commit -m "Добавлены/обновлены озёра"` → `git push`. Запуск двойным щелчком.
5. `README.md` с пошаговой инструкцией для заказчика.

### 9.2. Сценарий заказчика «добавить новое озеро»

1. Создать подпапку в `lakes/` с названием озера.
2. Положить в неё фотографии и файл `points on the map.txt` (3 ссылки).
3. Запустить `publish.bat`.
4. Через 2–5 минут на сайте появляется новая точка на карте и строка в списке.

Изменение или удаление озера — аналогично: правка/удаление подпапки и `publish.bat`.

## 10. Нефункциональные требования

- **Производительность:** главная страница без фото озёр весит не более ~1,5 МБ (включая подложку рельефа); первое отображение карты — до 2,5 с на мобильном 4G. Фото и Komoot загружаются только при открытии окна озера; миниатюры — «лениво» (`loading="lazy"`).
- **Адаптивность:** корректная работа от 360 px (телефон) до 2560 px ширины; без горизонтальной прокрутки страницы.
- **Браузеры:** последние 2 версии Chrome, Safari (включая iOS), Firefox, Edge.
- **Доступность:** точки на карте и строки списка доступны с клавиатуры (Tab/Enter); у модального окна — удержание фокуса внутри; у фото — `alt` с названием озера и номером фото; достаточный контраст подписей.
- **SEO/шеринг:** `<title>`, meta description, Open Graph-картинка (общая для сайта; для прямых ссылок на озеро — по возможности обложка озера).
- **Приватность:** из опубликованных фото удаляются EXIF-данные, включая GPS и модель телефона.
- **Независимость от внешних сервисов:** карта работает без внешних картографических API; внешние зависимости — только Google Fonts, встраивание Komoot и ссылки на Google Maps.

## 11. Вне рамок текущей версии

- Мультиязычность (только русский).
- Фильтры (по стране, сложности и т.п.), поиск.
- Линии маршрутов на схеме.
- Характеристики маршрута (дистанция, набор высоты, время, сложность), текстовые описания, даты походов.
- Тёмная тема, комментарии, система управления контентом (CMS).

Формат txt-файла (строки «ключ: значение») позволяет добавить эти поля позже без переделки существующих папок.

## 12. Критерии приёмки

1. Сайт опубликован на GitHub Pages и открывается по публичному адресу.
2. На карте отображаются все 5 текущих озёр в правильных местах (сверка с Google Maps: погрешность положения точки на схеме — не более ~1 км), подписи не перекрываются.
3. Клик по точке, по подписи и по строке списка открывает окно нужного озера; все три ссылки ведут на правильные адреса; встроенная карта Komoot показывает маршрут.
4. Галерея показывает все фото подпапки в правильной ориентации; лайтбокс листается стрелками, клавишами и свайпом.
5. Окно закрывается «×», `Esc`, кликом по фону и кнопкой «Назад»; прямая ссылка `#/lake/<slug>` открывает окно озера.
6. **Тест автоматического добавления:** в `lakes/` добавлена новая подпапка с фото и txt → запущен `publish.bat` → после завершения GitHub Actions на карте появилась новая точка и строка в списке без правки кода.
7. Подпапка с ошибкой (нет txt, битая ссылка) не ломает сборку; в логе есть понятное предупреждение.
8. Сайт корректно выглядит и работает на телефоне (iOS Safari, Android Chrome) и на десктопе.
9. В опубликованных фото отсутствуют GPS-данные EXIF.
10. `README.md` содержит понятную инструкцию по добавлению озера.

## 14. Риски и открытые вопросы

| Риск / вопрос | Предлагаемое решение |
|---|---|
| **Git внутри Dropbox.** Dropbox синхронизирует служебную папку `.git`, возможны конфликты и порча репозитория при работе с нескольких компьютеров. | Работать с репозиторием с одного компьютера; либо держать репозиторий вне Dropbox, а в Dropbox — только исходные фото. Решение за заказчиком до начала этапа 5. |
| **Размер репозитория.** Оригиналы фото 2–6 МБ каждое; при 100+ озёрах репозиторий превысит рекомендуемый GitHub лимит (~1 ГБ). | На старте хранить оригиналы. При росте — перед коммитом автоматически уменьшать фото до ~2500 px (опция в `publish.bat`) или использовать Git LFS. |
| **Раскрытие коротких ссылок Google** может перестать работать (изменение формата, блокировка запросов с серверов GitHub). | Кэш `data/geocache.json` (однажды полученные координаты больше не запрашиваются) + ручная строка `coords:`. Желательно раскрывать ссылки локально при запуске `publish.bat` и коммитить кэш. |
| **Встраивание Komoot** работает только для публичных маршрутов и может блокироваться браузером. | Всегда показывать прямую ссылку; iframe — дополнение. |
| **Озеро вне области подложки** (например, далеко во Франции). | Предупреждение при сборке; разовое расширение подложки рельефа исполнителем. |
| **Аккаунт GitHub** заказчика и желаемый адрес сайта (`<логин>.github.io/ozera-andorry` или собственный домен). | Уточнить до этапа 5. |
